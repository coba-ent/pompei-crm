# Requirements Quality Checklist: Gestión de precios de Mercado Libre — corrección de alcance

**Purpose**: Validar los puntos más riesgosos de la reescritura de esta spec: que el comportamiento
anterior (etiquetar Ventas) haya quedado inequívocamente removido sin residuos contradictorios, que el
disparo por evento esté especificado de forma testeable para los dos caminos de escritura conocidos, que
"pendiente"/"error"/"sincronizado" sean consistentes en todo el documento, y que el push inmediato al
cambiar la lista configurada (FR-007) tenga criterios medibles.
**Created**: 2026-07-29
**Feature**: [spec.md](../spec.md)

**Note**: This checklist is generated by the `/speckit-checklist` command based on feature context and requirements.

## Requirement Completeness

- [x] CHK001 - ¿Especifica la spec, en un requisito (no sólo en la Nota de revisión narrativa), que las
  Ventas convertidas desde Mercado Libre NO deben quedar etiquetadas con esta Lista de Precios? [Completeness, Spec §FR-020]
- [x] CHK002 - ¿Está definido qué pasa si un producto tiene precio cargado en la lista configurada pero
  **no** tiene vínculo vigente en el momento exacto del cambio — se descarta el evento sin dejar rastro,
  o queda algún estado recuperable (más allá del respaldo manual de US3)? [Completeness, Spec §User Story 2, §User Story 3 escenario 4]
- [x] CHK003 - ¿Está especificado si el guardado de la configuración debe validar que la Lista de Precios
  elegida exista, más allá de estar activa? [Completeness, Spec §FR-003]
- [x] CHK004 - ¿Están definidos los requisitos para el escenario "el vínculo se elimina mientras hay un
  envío de precio en curso o pendiente"? [Completeness, Spec §Edge Cases]

## Requirement Clarity

- [x] CHK006 - ¿Define la spec, sin ambigüedad, que "ambos caminos de escritura" se refiere

- [x] CHK007 - ¿Es "en el momento del cambio" (disparo inmediato) medible/verificable de forma objetiva,
  o podría interpretarse como "en algún momento cercano" sin un límite claro? [Clarity, Spec §FR-004, §SC-002]

## Requirement Consistency

- [x] CHK008 - ¿Usan todas las User Stories y Functional Requirements el mismo criterio de "producto

- [x] CHK009 - ¿Es consistente el uso de "pendiente" en toda la spec — ¿un vínculo con `error` se describe

- [x] CHK011 - ¿Es coherente el criterio de "sin validación de activa" (Assumptions) con el resto de la
